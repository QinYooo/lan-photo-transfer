# 原片直达：Android → Windows 局域网照片传输

一个离线运行的网页接收器。手机不用安装 App，电脑需要 **Python 3.10 或更高版本**。所有代码、网页和校验工具都包含在此文件夹内，无需 `pip install`，不用云服务、账号或 CDN。

## 三步开始

1. **电脑准备**：从 https://www.python.org/downloads/windows/ 安装官方 Python 3.10+。安装时勾选 **Add python.exe to PATH**。把整个压缩包解压到可写的短路径，例如 `D:\PhotoTransfer`。不要直接在压缩包内启动。
2. **电脑接收**：双击 `START_WINDOWS.bat`，保持黑色接收窗口打开。如果 Windows 防火墙询问，只允许你信任的 **专用网络**，不要勾选公用网络。程序会打开电脑浏览器，并在黑色窗口显示手机访问地址、连接码和保存目录。
3. **手机发送**：手机和电脑连接同一可信 Wi-Fi，在手机浏览器输入窗口中的 `http://电脑IPv4:8765/`，然后填写本次连接码。也可打开包含 `#token=...` 的完整链接。选择照片/视频或文件，点“开始传输”。保持网页在前台，手机不要锁屏。

只在手机浏览器输入电脑的局域网地址。`127.0.0.1` 和 `localhost` 是“本机”，不能用于手机连接电脑。电脑浏览器打开的页面用于检查程序已启动，不是手机传输必需的。

默认保存在程序旁的 `Photos_Inbox/transfer-日期-时间-随机值/`。每次启动新建一个文件夹。Windows 文件名中的非法字符会被替换，文件名末尾加随机标识，**不会覆盖同名照片**。每个文件保留原来的扩展名（过长异常扩展名会被省略）。

## 什么算传输成功？

- 手机先读取选择器交给网页的文件，分块计算 SHA-256。
- 电脑逐块接收原始字节并计算 SHA-256，和手机的值比较。
- 写入完成后先刷新文件到磁盘，再将完整文件原子放入目标目录；电脑重新读取目标文件，检查大小和 SHA-256。
- 成功记录写入 `transfer_manifest.jsonl` 后，网页才显示 **“手机原件与电脑文件 SHA-256 一致”**。
- 如果手机计算校验值失败，网页会明确询问是否仍上传。只有你同意才进行降级上传，并显示橙色 **“仅电脑自检，未校验手机与电脑字节一致”**。这不算两端校验成功，**不要据此删除手机原件**。
- “已发送 100%”不等于完成。必须等待电脑写入/复读校验回执。

普通 `http://192.168...` 局域网页面通常不能使用要求安全上下文的 Web Crypto `crypto.subtle`。本程序自带离线、增量的 JavaScript SHA-256，不依赖该接口，所以 HTTP 下仍可计算手机端哈希。哈希在 Web Worker 中按 1 MiB 读取，避免把大文件整体装进内存。**SHA-256 用于比较字节，不能抵挡不可信网络中的攻击者篡改页面或校验值，也不提供加密。**

程序不压缩、不转码，也不改写文件中的 EXIF 等内嵌元数据。它保证的是 **浏览器文件选择器提供的字节**：若相册或云盘选择器先导出、转换或下载了文件，程序无法证明它就是相机最初的原片。需要精确保留原片时，优先使用“选择其他文件”，在文件管理器中选 `DCIM/Camera` 下的本地文件。文件系统创建/修改时间不会自动还原；清单会记录浏览器提供的源文件修改时间（若有）。相册分组、收藏标记、相册数据库不会迁移。

## 上传后怎样安全整理手机

此网页没有申请手机文件的删除权限，也没有任何删除手机原件的功能。

1. 只筛选网页显示 **两端 SHA-256 一致** 的文件。橙色仅电脑自检、失败、暂停和未完成项都保留手机原件。
2. 到电脑保存目录确认文件数量、文件名、大小；打开一些照片/视频检查内容。
3. 建议复制到第二块硬盘或另一份独立备份，再在 Android 相册/文件管理器中 **手动删除已核对的对应原件**。不要直接清空整本相册或全部文件。
4. 先保留手机“最近删除”一段时间。单份电脑副本仍可能因误删、磁盘损坏或勒索软件丢失。

可在命令行复检电脑文件：

```text
py -3 verify_received.py "D:\PhotoTransfer\Photos_Inbox\transfer-实际日期时间"
```

复检只读取文件。它核对保存时的清单和当前字节，并区分原先两端一致与仅电脑自检。清单不是数字签名，不能防止有电脑访问权的人同时修改文件和清单，也不能代替独立备份。

## 安全边界

- 只在自己的可信私人 Wi-Fi 使用。**HTTP 不加密**，同网络的攻击者可能偷看文件/连接码或篡改流量。连接码不是加密。
- 每次启动生成新的高强度随机连接码；网页从链接片段读取后从地址栏移除，并仅在本标签页的 sessionStorage 暂存。不要把完整链接或连接码公开给别人。退出程序即停止接收；关闭手机标签页可清除该标签页存储。
- 接收器默认监听电脑所有 IPv4 网卡，需要 Windows 防火墙限制为专用网络。不要做路由器端口转发，不要把端口暴露到公网，不要关闭防火墙。可用 `--host 电脑局域网IPv4` 限定一张网卡。
- 不调用外部服务，不上传云端，不提供已接收文件下载/浏览接口。静态网页本身无需连接码，上传和回执需要连接码。
- 文件名经过安全处理；临时文件在 `.partial`，校验通过后才记录成功。程序不会执行上传文件，不要打开来历不明的可执行文件。
- 本工具适用于家中少量设备，不是面向不可信网络的生产级服务器。最多同时接收 2 个文件、24 个连接；单次读取无数据 60 秒超时。默认单文件上限 8 GiB。文件系统本身也有限制，例如 FAT32 不能保存 4 GiB 或更大的单文件。

## 重试、暂停与中断

- 上传按顺序进行，可以继续添加文件。停止按钮会取消当前请求并停止后面的队列，不会删除手机原件。
- 同一网页中重试时先用稳定上传编号查询回执，避免成功响应丢失导致重复保存。接收程序还在校验时需要稍后再重试。
- 没有断点续传：未成功的文件重试时从头发送。Android 后台、锁屏、省电或切 Wi-Fi 都可能中断。
- **刷新/关闭网页会丢失选择列表和重试编号**。重复选择、刷新后重新传或重启接收器后重传，可能生成额外副本，但不会覆盖旧文件。重新传之前先检查电脑目录。
- 每次重启换连接码及会话目录，旧会话不能从网页查询；已保存照片和本地清单仍保留。
- 强制结束进程或断电可能留下 `.partial` 中的临时文件，极端情况下也可能留下没有成功清单的目标文件。它们都不算成功备份。关闭程序后可清理临时文件，保留手机原件并重传。

## 常见问题

**手机打不开网页**：检查是否同一网络，电脑 IP 是否正确；使用 `http://` 而非 `https://`；检查 Windows 专用网络防火墙。公司/酒店/访客 Wi-Fi 可能启用了设备隔离。不要为解决此问题关闭防火墙或开放公网。

**连接码无效**：电脑每次重启会换新码。重新输入黑色窗口中的本次连接码。

**端口被占用**：在此文件夹打开命令行，运行 `py -3 receiver.py --port 8766`，手机也改用 8766。

**改保存路径**：运行 `py -3 receiver.py --output "D:\PhonePhotos"`。程序会在此路径下新建本次传输子文件夹。确保磁盘空间充足；不要放在系统目录、只读目录或路径过深的位置。

**其他选项**：`py -3 receiver.py --help`。例如 `--no-browser` 不自动开电脑网页，`--max-file-mb 2048` 限制单文件 2 GiB。

## 文件说明与验证

- `START_WINDOWS.bat`：Windows 双击启动。
- `receiver.py`：Python 标准库接收端。
- `static/`：本地网页、样式、SHA-256 实现及后台校验线程。
- `verify_received.py`：只读复检工具。
- `tests/`：自动化测试；运行 `py -3 -m unittest discover -s tests -v`。JavaScript 校验测试需要 Node.js，仅开发测试需要，正常使用不用安装 Node。

该版本在 Linux 环境自动测试 HTTP 接收、哈希、异常/拒收、重试和文件保存逻辑。没有在真实 Windows 电脑或 Android 手机上实机测试，不宣称已经完成跨设备验收。Windows 批处理、防火墙提示、手机选择器和系统后台行为仍须在你的设备上确认。
